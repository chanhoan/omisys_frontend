OMISYS · 고객용 전체 기능 디자인

OMI 디자인 세트

백엔드 chanhoan/omisys와 프론트엔드 chanhoan/omisys_frontend의 API 계약(9종 OpenAPI · zod contracts)을 기준으로, 고객용 전 기능의 모든 화면과 모든 상태를 설계했다. 스타일은 기존 방향(Apple 계열 · Pretendard · 라운드 28)을 유지하되, 기존 CSS에 남아 있던 결함을 함께 정리했다.

산출물은 실제 제품 CSS를 그대로 쓰는 HTML 페이지다. 클래스명이 저장소와 100% 일치하므로 마크업을 그대로 옮길 수 있다.

기존 스타일에서 고친 것

omi.css — globals.css 교체본

기존 globals.css는 에디토리얼 세리프 시스템 위에 Apple 시스템을 덧칠한 3중 레이어였고, 아래쪽 규칙이 위쪽을 덮다 만 잔재가 남아 있었다. 클래스명은 전부 유지했으므로 저장소 JSX는 수정 없이 동작한다.

01

웜 베이지 잔재 제거. #e6e2d9 #e5e1d8 #cac7bf #aaa69e가 쿨 그레이 토큰(--surface-muted:#e8e8ed)과 한 화면에 공존했다. 전부 토큰으로 대체.

02

토큰 밖 임의 색 정리. 세일가·에러의 러스트 레드 #8b2f20 → --danger, 장바구니 배지 #000 → --accent, 상태 배지 #1a3a1a/#3a1a1a → 상태별 소프트 토큰.

03

레거시 별칭 사용 중단. --ink/--muted/--paper/--line과 --text/--border가 파일 안에서 섞여 쓰였다. 신규 규칙은 후자만 사용하고, 별칭은 호환용으로만 남겼다.

04

다크모드 실제 동작. 정의는 있었지만 #fff·#1d1d1f·베이지 하드코딩이 많아 깨졌다. 이미지 위 텍스트를 제외한 모든 색을 토큰화했다. 캠페인 밴드처럼 의도적으로 어두운 영역은 --band/--band-text 전용 쌍으로 분리해 양 테마에서 흰 글씨 대비를 유지한다. 각 문서 우상단에서 라이트/다크를 전환해 확인할 수 있다.

05

중복 정의 통합. .section 3중, .eyebrow 2중 정의를 각 1회로. .order-summary가 장바구니와 주문상세에서 다른 의미로 쓰이던 충돌을 .order-summary(요약 카드)와 .order-amounts(금액 내역)로 분리.

06

레이아웃 버그. .button{gap:28px}(아이콘이 라벨에서 28px 떨어짐) → 8px. .campaign-copy h2{white-space:nowrap}은 한글에서 넘쳐 제거. .filter-bar .sort-button:first-of-type{margin-left:auto}는 :first-of-type이 형제 중 첫 button을 가리켜 매칭되지 않던 규칙 — 인접 형제 조합으로 수정.

07

가독성. 9~10px 텍스트(배지·메타·브랜드·아코디언 본문)를 11px 이상, 본문은 13.5px 이상으로. 폼 입력 높이 38px → 44px로 올려 모바일 터치 기준을 맞췄다.

08

서체 이원화 종료. 세리프 --font-display가 절반만 덮여 같은 페이지 안에서 제목 서체가 달랐다(이벤트·장바구니 상품명·계정 링크). Pretendard 단일로 통일하고 letter-spacing을 크기별로 조정.

09

숫자 정렬. 가격·수량·포인트·주문번호에 font-variant-numeric: tabular-nums를 적용해 목록에서 자릿수가 흔들리지 않게 했다.

10

스켈레톤. 배경이 테두리색 --line이라 카드가 아니라 선처럼 보였다. --surface-muted + 카드 라운드로 실제 자리와 겹치게 수정.

11

on-tint 대비. --accent는 흰 배경 기준값이라 밝은 틴트(--accent-soft) 위 전경으로 쓰면 4.12:1로 AA 미달이었다 — warning·success·danger 형제는 전경을 별도의 짙은 값으로 잡아 5.1~5.8:1을 얻고 있어 accent만 누락이었다. on-tint 전용 --accent-strong(라이트 #0057b0 = 6.17:1)을 추가해 배송중 배지, 정보 배너, 내 리뷰·기본배송지 배지, 할인 금액, .more-link에 적용했다. 버튼·링크의 --accent 값은 그대로 유지.

12

한국어 줄바꿈. 한국어는 word-break 기본값에서 글자 단위로 끊기므로 “추천 검색어로 / 도” 같은 어절 중간 분리가 생겼다. word-break:keep-all로 어절을 지키고, 나아가 본문을 문장당 한 블록(.s)으로 나눠 한 문장이 여러 줄로 쪼개지지 않게 했다. 전 페이지 63개 문장을 측정해 한 줄에 들어가는지 확인했고, 사이드바처럼 좁은 칼럼에서는 문장 자체를 짧게 다듬었다.

13

화면 문구에서 기술 용어 제거. 사용자가 알 필요 없는 구현 사항이 UI 본문에 들어가 있었다 — 검색 엔진 이름, 결제사와 복구 경로, 중복방지 헤더명, 기기 등록 엔드포인트. 모두 사용자 언어로 바꿨다. 개발자용 설명은 화면 밖 주석에만 남긴다.

14

금액·수량 줄바꿈 방지. keep-all을 켜자 금액이 한 덩어리 단어가 되어, 좁은 사이드바에서 overflow-wrap이 숫자 중간을 끊었다(₩297,00 / 0). 금액·수량·운송장 같은 수치 슬롯은 white-space:nowrap으로 고정하고, 라벨 쪽만 줄어들게 했다.

15

주문 상품 행 정렬. .checkout-items li가 justify-content:space-between이라 상품명 길이에 따라 수량 위치가 행마다 어긋났다. minmax(0,1fr) 3.5em auto 그리드로 바꿔 수량과 금액이 세로 축으로 정렬된다.

구현 전 확인이 필요한 사항

백엔드 · 프론트 협의
디자인만으로는 해결되지 않는 항목입니다.
  • 대기열 202 계약 — 게이트웨이가 대기 시 빈 body 200을 반환하면 정상 성공과 구분할 수 없습니다. 202 + { rank, retryAfterSeconds } 응답이 전제입니다.
  • Idempotency-Key 처리 — 프론트는 전송하지만 주문 서비스에 수신 처리 코드가 확인되지 않았습니다. 중복 결제 방지 문구는 백엔드 구현을 가정합니다.
  • 장바구니 비우기 시점 — 현재 결제창 이동 전에 clear()가 호출되어 결제 실패 시 장바구니가 복구되지 않습니다. 결제 확정 후로 옮기는 것을 권장합니다.
  • 리뷰 캐시 — getReviews가 revalidate: 30이라 작성·수정 직후 목록이 최대 30초간 옛 데이터입니다. 낙관적 갱신 또는 태그 무효화가 필요합니다.
  • 재입고 알림 — 품절 대체 행동으로 설계했으나 대응 엔드포인트가 계약에 없습니다.
  • 관리자 콘솔 — 관리자용 51개 API는 이번 범위에서 제외했습니다.
